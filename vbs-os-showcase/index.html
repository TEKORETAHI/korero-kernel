Architecture

Small kernel. Big projection space.

The value is not NOR gates by themselves. It is the closed system around them: one seed, one state fabric, one scheduler and many process projections.

01 / BOOT

Seed

A compact boot image initializes the machine. Change the seed, change the starting world.

02 / FABRIC

NOR state

Binary registers form the persistent substrate that every process reads from and writes to.

03 / KERNEL

Processes + IPC

A scheduler gives projections PIDs, capabilities, local state and a message bus.

04 / DISPLAY

Projection

Touch interfaces, games, tools and workflows are rendered views of the same running machine.

Why it matters

Stop rebuilding the runtime for every app.

Traditional app stacks duplicate shells, state logic and deployment work. VBS experiments with installing the machine once and delivering new behaviour as process/seed projections.

Traditional app model

01New workflow often means another application bundle.
02State is fragmented between products.
03UI and backend behaviour are tightly coupled.
04More code paths means more maintenance surfaces.

VBS OS model

01Install one runtime; project many workflows.
02Processes share a common state fabric.
03Touch becomes a direct state transition.
04Intelligence can propose seeds without owning the trusted kernel.
